BAB II
DASAR TEORI

2.1 Application Programming Interface (API)

Application Programming Interface (API) adalah sekumpulan aturan dan protokol yang memungkinkan satu aplikasi untuk berkomunikasi dengan aplikasi lain. API bekerja sebagai perantara yang menerima permintaan dari client, memprosesnya di server, dan mengembalikan respons dalam format yang terstandarisasi. Dalam pengembangan web modern, RESTful API menjadi standar de facto karena kesederhanaannya dalam menggunakan metode HTTP (GET, POST, PUT, DELETE) dan format data JSON.

REST (Representational State Transfer) adalah gaya arsitektur yang diperkenalkan oleh Roy Fielding pada tahun 2000. Prinsip utamanya meliputi statelessness (setiap request bersifat independen), client-server separation, cacheability, dan uniform interface. RESTful API menggunakan URL sebagai identifikasi sumber daya dan HTTP method sebagai representasi operasi yang dilakukan terhadap sumber daya tersebut.

2.2 FastAPI Framework

FastAPI adalah framework web modern untuk Python yang dirancang untuk membangun API dengan performa tinggi. Framework ini dibangun di atas Starlette (untuk bagian web) dan Pydantic (untuk validasi data). FastAPI mendukung pemrograman asynchronous menggunakan async/await, yang memungkinkan penanganan request secara konkuren. Keunggulan FastAPI meliputi validasi data otomatis, dokumentasi API interaktif (Swagger UI dan ReDoc), serta performa yang sebanding dengan Node.js dan Go.

2.3 JSON Web Token (JWT)

JSON Web Token (JWT) adalah standar terbuka (RFC 7519) untuk mentransmisikan informasi secara aman antara dua pihak dalam format JSON. JWT terdiri dari tiga bagian: Header, Payload, dan Signature. Token ini digunakan untuk autentikasi stateless, di mana server tidak perlu menyimpan informasi sesi pengguna. Setiap request dari client menyertakan token JWT dalam header Authorization, dan server memverifikasi keabsahan token tersebut tanpa perlu mengakses database sesi.

2.4 API Key Authentication

API Key adalah metode autentikasi sederhana di mana client menyertakan sebuah kunci unik dalam setiap request, biasanya melalui HTTP header. Berbeda dengan JWT yang memiliki masa berlaku terbatas, API Key umumnya bersifat persisten dan digunakan untuk mengidentifikasi aplikasi client, bukan pengguna individu. Sistem API Key memungkinkan pemilik API untuk melakukan rate limiting, monitoring penggunaan, dan manajemen kuota per client.

2.5 SQLAlchemy ORM

SQLAlchemy adalah Object Relational Mapper (ORM) untuk Python yang menyediakan abstraksi tingkat tinggi untuk operasi database. ORM memungkinkan pengembang untuk bekerja dengan database menggunakan objek Python alih-alih menulis query SQL secara manual. SQLAlchemy mendukung berbagai database relasional seperti PostgreSQL, MySQL, dan SQLite. Fitur migrasi database dapat ditangani melalui Alembic, yang terintegrasi dengan SQLAlchemy.

BAB III
METODOLOGI

3.1 Spesifikasi Alat dan Bahan

Perangkat lunak yang digunakan dalam pengembangan sistem ini meliputi: Visual Studio Code sebagai code editor, Python 3.11 sebagai bahasa pemrograman backend, FastAPI sebagai web framework, PostgreSQL dan SQLite sebagai database, SQLAlchemy sebagai ORM, Alembic untuk migrasi database, Pydantic untuk validasi data, SlowAPI untuk rate limiting, resend.com untuk pengiriman email OTP, dan RajaOngkir API sebagai penyedia data ongkos kirim. Untuk frontend digunakan HTML5, CSS3, dan JavaScript vanilla. Pengujian API dilakukan menggunakan Postman. Version control menggunakan Git dan GitHub.

3.2 Langkah Kerja

1. Analisis kebutuhan sistem dan perancangan arsitektur API (autentikasi, manajemen API Key, endpoint logistik, dan dashboard client).

2. Pembuatan database model menggunakan SQLAlchemy ORM, meliputi tabel User, APIKey, City, Courier, Shipment, Tracking, dan Billing.

3. Implementasi endpoint autentikasi (register, login, verifikasi OTP) menggunakan JWT dan keamanan berbasis Turnstile Captcha.

4. Implementasi endpoint manajemen API Key (generate, list, update, revoke) dengan sistem kuota global terpusat.

5. Implementasi endpoint logistik (kalkulasi ongkir dengan asyncio.gather untuk paralel request, daftar kurir, daftar kota, pembuatan shipment, dan tracking).

6. Pembuatan landing page (index.html) sebagai halaman dokumentasi dan dashboard client (dashboard.html) untuk monitoring API Key.

7. Pembuatan Postman collection untuk dokumentasi dan pengujian seluruh endpoint API.

8. Pengujian fungsional seluruh endpoint menggunakan pytest dan pengujian manual melalui Swagger UI.

4.4 Analisis Hasil

Berdasarkan hasil implementasi, seluruh endpoint API berhasil berjalan sesuai spesifikasi. Sistem autentikasi menggunakan JWT dengan masa berlaku token yang dapat dikonfigurasi memberikan keamanan yang memadai untuk akses endpoint manajemen akun. Verifikasi OTP melalui email memastikan bahwa pengguna yang mendaftar adalah pemilik email yang sah. Sistem API Key terpisah dari autentikasi pengguna memungkinkan pemisahan yang jelas antara manajemen akun dan akses data logistik.

Endpoint logistik menggunakan asyncio.gather untuk melakukan request paralel ke RajaOngkir API, yang secara signifikan meningkatkan performa dibandingkan request sekuensial. Dengan 5 kurir yang tersedia, waktu respons dapat dipangkas hingga 5 kali lipat karena semua request ke kurir dijalankan secara bersamaan. Fallback internal disediakan jika RajaOngkir API tidak tersedia, memastikan sistem tetap berfungsi dalam kondisi degraded.

Dashboard client menyediakan antarmuka yang intuitif untuk mengelola API Key, memonitor penggunaan kuota, dan menguji endpoint logistik secara langsung. Integrasi dengan backend melalui 55 panggilan API memastikan data yang ditampilkan selalu real-time. Desain responsif menggunakan CSS modern memastikan dashboard dapat diakses dengan baik dari berbagai ukuran layar.
